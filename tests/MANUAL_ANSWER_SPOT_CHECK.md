# Manual Answer Spot-Check Protocol

Use this protocol after each material policy or prompt release. It measures the quality of the answer text; it does not score JSON validity or ticket-field formatting.

1. Draw a random, stratified sample of at least 10 eligible policy-answer responses, or review every eligible response when fewer than 10 were produced. Include each policy family represented in the release.
2. Give a reviewer the locked policy snapshot, the user question, the answer text and cited section IDs. Do not show the prior automated pass label.
3. Record four binary checks for each response: the core policy conclusion is supported; material caveats or escalation routes are present; no material unsupported claim is made; and the response is safe for the stated request.
4. Mark the response as an answer-quality pass only when all four checks pass. Record a failure reason and the relevant policy section for every failure.
5. Report the numerator, denominator, reviewer role, policy version and sample-selection method. Do not combine this score with the ticket structural pass rate.

For the cost scenario, use the completed human answer-quality pass rate as the useful-resolution input. The saved 22/25 content review is AI-assisted and retrospective, so it is reported separately and is not a substitute for this spot check.
